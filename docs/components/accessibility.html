Accessibility Utilities

The low-level building blocks the components are made of — hidden labels, separators, live regions, announcements, hotkeys, focus scopes, reading direction and roving focus.

Visually hidden

BhVisuallyHidden hides content visually but keeps it in the accessibility tree — the label of an icon-only button is read as "Edit", "Notifications", "Delete". With Focusable="true" the content is revealed while keyboard focus is inside it: Tab into this demo to uncover the skip link.

Example

Razor

@* Skip link: hidden until it receives keyboard focus *@
<BhVisuallyHidden Focusable="true">
    <a href="accessibility#a11y-skip-target" class="a11y-skip-link"
       @onclick="SkipToContent" @onclick:preventDefault>Skip to content</a>
</BhVisuallyHidden>

@* Icon-only buttons: the hidden text is the accessible name *@
<button type="button" class="a11y-icon-button">
    <svg viewBox="0 0 24 24" ... aria-hidden="true" focusable="false">…</svg>
    <BhVisuallyHidden>Edit</BhVisuallyHidden>
</button>
<button type="button" class="a11y-icon-button">
    <svg viewBox="0 0 24 24" ... aria-hidden="true" focusable="false">…</svg>
    <BhVisuallyHidden>Notifications</BhVisuallyHidden>
</button>

<div id="a11y-skip-target" tabindex="-1" class="a11y-skip-target" @ref="skipTarget">
    Main content — the skip link moves focus here.
</div>

@code {
    private ElementReference skipTarget;

    private async Task SkipToContent() => await skipTarget.FocusAsync();
}

Separator

BhSeparator renders role="separator" (plus aria-orientation="vertical" when Orientation is vertical) so assistive tech announces the boundary between groups of content. When the line is purely visual, Decorative="true" renders role="none" instead. Both emit data-orientation for styling.

Example

Razor

<div class="a11y-sep-card">
    <p class="a11y-sep-title">BlazorHeadless</p>
    <p class="a11y-sep-text">Unstyled, accessible components for Blazor.</p>

    <BhSeparator class="a11y-separator" />                       @* role="separator" *@

    <div class="a11y-sep-row">
        <span>Docs</span>
        <BhSeparator Orientation="BhOrientation.Vertical"          @* + aria-orientation="vertical" *@
                     class="a11y-separator" />
        <span>Source</span>
        <BhSeparator Orientation="BhOrientation.Vertical" class="a11y-separator" />
        <span>Changelog</span>
    </div>
</div>

@* Purely visual divider: role="none" *@
<div class="a11y-or">
    <BhSeparator Decorative="true" class="a11y-separator" />
    or
    <BhSeparator Decorative="true" class="a11y-separator" />
</div>

Live regions

BhLiveRegion is rendered from the first render (live regions must exist before their content changes), so updating its content is announced. Polite regions (role="status") wait for the user to be idle; assertive ones (role="alert") interrupt — reserve them for urgent problems. Set VisuallyHidden="true" to announce without showing.

Example

Razor

<BhButton OnClick="SaveDraft" class="btn">Save draft</BhButton>

@* Polite: role="status" aria-live="polite" *@
<BhLiveRegion class="a11y-status">@draftStatus</BhLiveRegion>

<BhButton OnClick="ToggleConnection" class="btn">
    @(offline ? "Reconnect" : "Simulate connection loss")
</BhButton>

@* Assertive: role="alert" aria-live="assertive" *@
<BhLiveRegion Politeness="BhPoliteness.Assertive" class="a11y-alert">@alertText</BhLiveRegion>

@* Announce without showing anything *@
@* <BhLiveRegion VisuallyHidden="true">@resultCount results</BhLiveRegion> *@

@code {
    private string? draftStatus;
    private string? alertText;
    private bool offline;

    private void SaveDraft() => draftStatus = $"Draft saved at {DateTime.Now:HH:mm:ss}.";

    private void ToggleConnection()
    {
        offline = !offline;
        alertText = offline ? "Connection lost. Changes will sync when you are back online." : null;
    }
}

CSS

/* All styles are consumer-authored — the library ships zero CSS */
.a11y-status { color: #15803d; font-size: 0.875rem; }

/* The alert region stays rendered (and empty) until there is something to say */
.a11y-alert:not(:empty) {
    padding: 0.5rem 0.75rem;
    border: 1px solid #fecaca;
    border-radius: 0.5rem;
    background: #fef2f2;
    color: #991b1b;
    font-size: 0.875rem;
}

Announcer

For fire-and-forget messages from code, inject IBhAnnouncer and call AnnounceAsync. It writes to one shared, visually hidden live region (the one toasts and drag-and-drop use too), so nothing needs to be rendered. The log below only mirrors what a screen reader hears.

Example

Razor

@inject IBhAnnouncer Announcer

@foreach (var product in Products)
{
    <div class="a11y-product">
        <strong>@product</strong>
        <BhButton OnClick="() => AddToCartAsync(product)" class="btn">Add to cart</BhButton>
    </div>
}
<BhButton OnClick="EmptyCartAsync" class="btn btn-link">Empty cart (assertive)</BhButton>

@code {
    private static readonly string[] Products = ["Notebook", "Fountain pen", "Desk lamp"];
    private int cartCount;

    private async Task AddToCartAsync(string product)
    {
        cartCount++;
        await Announcer.AnnounceAsync($"{product} added to cart. {cartCount} item(s) in your cart.");
    }

    private async Task EmptyCartAsync()
    {
        cartCount = 0;
        await Announcer.AnnounceAsync("Cart emptied.", BhPoliteness.Assertive);
    }
}

CSS

/* All styles are consumer-authored — the library ships zero CSS.
   The announcer's live region is visually hidden — nothing to style. */
.a11y-products { display: flex; flex-wrap: wrap; gap: 0.75rem; }

.a11y-product {
    display: flex;
    flex-direction: column;
    gap: 0.5rem;
    min-width: 10rem;
    padding: 0.85rem 1rem;
    border: 1px solid #e4e4e7;
    border-radius: 0.75rem;
    background: #fff;
}

.a11y-log {
    padding: 0.6rem 0.85rem 0.6rem 2rem;
    border-radius: 0.5rem;
    background: #18181b;
    color: #d4d4d8;
    font-family: ui-monospace, monospace;
    font-size: 0.75rem;
}

Hotkeys

BhHotkey registers a global shortcut while it is rendered and renders nothing. mod is ⌘ on Apple platforms and Ctrl elsewhere. Shortcuts without Ctrl / ⌘ (like shift+?) are ignored while typing in a text field unless AllowInInputs is set. Advertise shortcuts with aria-keyshortcuts.

Example

Razor

<BhHotkey Keys="mod+k" OnTriggered="FocusSearchAsync" />
<BhHotkey Keys="shift+?" OnTriggered="ToggleShortcuts" />

<div class="a11y-search">
    <input @ref="searchInput" type="search" placeholder="Search components…"
           aria-label="Search components" aria-keyshortcuts="Control+K Meta+K"
           class="a11y-input" />
    <span class="a11y-search-hint" aria-hidden="true">
        <kbd class="a11y-kbd">Ctrl</kbd><kbd class="a11y-kbd">K</kbd>
    </span>
</div>

<BhButton OnClick="ToggleShortcuts" aria-expanded="@(showShortcuts ? "true" : "false")"
          aria-keyshortcuts="Shift+?" class="btn">
    Keyboard shortcuts <kbd class="a11y-kbd">?</kbd>
</BhButton>

@if (showShortcuts)
{
    <section class="a11y-shortcuts" aria-label="Keyboard shortcuts">…</section>
}

@code {
    private ElementReference searchInput;
    private bool showShortcuts;

    private async Task FocusSearchAsync() => await searchInput.FocusAsync();

    private void ToggleShortcuts() => showShortcuts = !showShortcuts;
}

Focus scope and focus trap

BhFocusScope manages focus for a region: it moves focus inside when it activates, can trap Tab / Shift+Tab (Trapped) or just wrap it (Loop), and restores focus to where it was when it deactivates. BhFocusTrap is the same component with Trapped on by default. Click "Edit profile": focus lands on the first field and stays in the form; Save, Cancel or Escape return it to the button.

Example

Razor

<BhButton OnClick="StartEditing" aria-expanded="@(editing ? "true" : "false")" class="btn">
    Edit profile
</BhButton>

@if (editing)
{
    @* Auto-focuses the first field, traps Tab, and restores focus to
       "Edit profile" when it is removed. <BhFocusTrap> = Trapped by default. *@
    <BhFocusScope Trapped="true" RestoreFocus="true" class="a11y-scope"
                  aria-label="Edit profile" role="group" @onkeydown="OnScopeKeyDown">
        <label class="a11y-field">
            <span>Name</span>
            <input class="a11y-input" @bind="draftName" />
        </label>
        <label class="a11y-field">
            <span>Email</span>
            <input class="a11y-input" type="email" @bind="draftEmail" />
        </label>
        <div class="a11y-actions">
            <button type="button" class="btn" @onclick="CancelEditing">Cancel</button>
            <button type="button" class="btn btn-primary" @onclick="SaveProfile">Save</button>
        </div>
    </BhFocusScope>
}

@code {
    private bool editing;

    private void OnScopeKeyDown(KeyboardEventArgs e)
    {
        if (e.Key == "Escape") editing = false;
    }

    // StartEditing / SaveProfile / CancelEditing toggle `editing`.
}

    display: flex;
    flex-direction: column;

Reading direction

BhDirectionProvider cascades the reading direction to every component below it. In RTL, Left / Right arrow keys are mirrored: ArrowLeft moves to the next radio or tab. Set the HTML dir attribute as well so the layout flips; a component's own Dir parameter takes precedence.

Example

Razor

<div dir="@direction.ToAttribute()" class="a11y-dir-preview">   @* flips the layout *@
    <BhDirectionProvider Dir="direction">                      @* flips the arrow keys *@
        <BhRadioGroup Vertical="false" DefaultValue="m" aria-label="Size" class="a11y-radio-segments">
            <BhRadio Value="s" class="a11y-radio-segment">Small</BhRadio>
            <BhRadio Value="m" class="a11y-radio-segment">Medium</BhRadio>
            <BhRadio Value="l" class="a11y-radio-segment">Large</BhRadio>
        </BhRadioGroup>

        <BhTabGroup>
            <BhTabList aria-label="Project" class="a11y-tab-list">
                <BhTab class="a11y-tab">Overview</BhTab>
                <BhTab class="a11y-tab">Activity</BhTab>
                <BhTab class="a11y-tab">Settings</BhTab>
            </BhTabList>
            <BhTabPanels>
                <BhTabPanel class="a11y-tab-panel">…</BhTabPanel>
                <BhTabPanel class="a11y-tab-panel">…</BhTabPanel>
                <BhTabPanel class="a11y-tab-panel">…</BhTabPanel>
            </BhTabPanels>
        </BhTabGroup>
    </BhDirectionProvider>
</div>

@code {
    private BhDirection direction = BhDirection.Rtl;
}

Roving focus

BhRovingFocusGroup + BhRovingFocusItem implement a roving tabindex for your own composite widgets: the group is a single Tab stop, arrow keys (per Orientation) and Home / End move between items, disabled items are skipped and the last focused item is remembered. Give the group the role that matches your widget — here a toolbar of toggle chips.

Example

Razor

<BhRovingFocusGroup role="toolbar" aria-label="Filter by tag" class="a11y-chips">
    @foreach (var tag in Tags)
    {
        <BhRovingFocusItem Disabled="@(tag == "Archived")"
                           aria-pressed="@(selectedTags.Contains(tag) ? "true" : "false")"
                           @onclick="() => ToggleTag(tag)"
                           class="a11y-chip">
            @tag
        </BhRovingFocusItem>
    }
</BhRovingFocusGroup>

@code {
    private static readonly string[] Tags = ["Design", "Engineering", "Marketing", "Archived", "Support"];
    private readonly HashSet<string> selectedTags = new() { "Engineering" };

    private void ToggleTag(string tag)
    {
        if (!selectedTags.Remove(tag)) selectedTags.Add(tag);
    }
}
