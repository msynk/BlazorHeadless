Sortable

Reorder a list by dragging with a pointer or entirely with the keyboard, with live screen-reader announcements.

Reorderable task list

Bind the list with @@bind-Items; ItemKey keeps each row's identity stable and ItemLabel names it in announcements. Drag a grip with a mouse, pen or finger — or focus a grip, press Space / Enter to pick the task up, ↑ / ↓ to move it, Space / Enter to drop it and Escape to cancel. Each step is announced automatically.

Example

Razor

<BhSortable TItem="TaskItem" @bind-Items="tasks"
            ItemKey="t => t.Id" ItemLabel="t => t.Title"
            aria-label="Tasks" class="sortable-list" Context="s">
    <BhSortableHandle TItem="TaskItem" class="sortable-handle"
                      aria-label="@($"Reorder {s.Item.Title}")">⠿</BhSortableHandle>
    <span class="sortable-title">@s.Item.Title</span>
    <span class="sortable-tag">@s.Item.Tag</span>
</BhSortable>

<p class="sortable-output">
    Bound order (ids): <strong>@string.Join(" · ", tasks.Select(t => t.Id))</strong>
</p>

@code {
    public sealed record TaskItem(int Id, string Title, string Tag);

    // Declare the field with the parameter's type (IList<T>) so @bind-Items infers cleanly.
    private IList<TaskItem> tasks =
    [
        new(1, "Write release notes", "Docs"),
        new(2, "Fix flaky login test", "Bug"),
        new(3, "Review pull requests", "Team"),
        new(4, "Update dependencies", "Chore"),
    ];
}

OnReorder event log

OnReorder fires once per committed move with the item and its old and new index — handy for persisting the order or sending a PATCH. Moves cancelled with Escape (or dropped in place) don't fire it.

Example

Razor

<BhSortable TItem="string" @bind-Items="backlog" OnReorder="LogReorder"
            aria-label="Sprint backlog" class="sortable-list" Context="s">
    <BhSortableHandle TItem="string" class="sortable-handle"
                      aria-label="@($"Reorder {s.Item}")">⠿</BhSortableHandle>
    <span class="sortable-title">@s.Item</span>
</BhSortable>

<ol class="sortable-log" aria-label="Reorder events">
    @if (reorderLog.Count == 0)
    {
        <li class="sortable-log-empty">No moves yet — reorder an item.</li>
    }
    @foreach (var entry in reorderLog)
    {
        <li>@entry</li>
    }
</ol>

@code {
    private IList<string> backlog = ["Login page", "Password reset", "Audit log", "Dark mode", "CSV export"];
    private readonly List<string> reorderLog = [];

    private void LogReorder(BhReorderEventArgs<string> e)
    {
        reorderLog.Insert(0, $"“{e.Item}” moved from index {e.OldIndex} to {e.NewIndex}");
        if (reorderLog.Count > 6) reorderLog.RemoveAt(reorderLog.Count - 1);
    }
}

Horizontal orientation

Set Orientation="BhOrientation.Horizontal" for a row: pointer drags shift siblings sideways and, once picked up, ← / → move the item. Here the whole chip is the BhSortableHandle, so its text becomes the accessible name.

Example

Razor

<BhSortable TItem="string" @bind-Items="priorities"
            Orientation="BhOrientation.Horizontal"
            aria-label="Priorities" class="sortable-row" Context="s">
    @* The whole chip is the handle: pointer drags and keyboard both start here. *@
    <BhSortableHandle TItem="string" class="sortable-chip">
        <span class="sortable-chip-grip" aria-hidden="true">⠿</span>@s.Item
    </BhSortableHandle>
</BhSortable>

<p class="sortable-output">
    Ranking: <strong>@string.Join(" › ", priorities)</strong>
</p>

@code {
    private IList<string> priorities = ["Speed", "Quality", "Cost", "Scope"];
}

Custom announcements

Pass a BhSortableAnnouncements to localize or reword what screen readers hear: the Instructions every handle is described by, plus the PickedUp, Moved, Dropped and Cancelled messages. The template's Index is the live (preview) position.

Example

Razor

<BhSortable TItem="string" @bind-Items="queue" Announcements="queueAnnouncements"
            aria-label="Up next" class="sortable-list" Context="s">
    <BhSortableHandle TItem="string" class="sortable-handle"
                      aria-label="@($"Move {s.Item}")">⠿</BhSortableHandle>
    <span class="sortable-index">@(s.Index + 1)</span>
    <span class="sortable-title">@s.Item</span>
</BhSortable>

@code {
    private IList<string> queue = ["Blue in Green", "So What", "Naima", "Take Five"];

    private readonly BhSortableAnnouncements queueAnnouncements = new()
    {
        Instructions = "Press Space to grab a song. Use the up and down arrows to change its place in the queue, Space to drop it, or Escape to cancel.",
        PickedUp = (song, position, count) => $"Grabbed {song}. It plays as number {position} of {count}.",
        Moved = (song, position, count) => $"{song} now plays as number {position} of {count}.",
        Dropped = (song, position, _) => position == 1 ? $"{song} plays next." : $"{song} plays as number {position}.",
        Cancelled = (song, position) => $"Cancelled. {song} stays at number {position}.",
    };
}

Disabled

Disabled="true" stops pointer and keyboard reordering. The root and every item get data-disabled and the handles aria-disabled="true". The lock below is a BhToggle.

Example

Razor

<BhToggle @bind-Pressed="locked" class="sortable-lock">Lock order</BhToggle>

<BhSortable TItem="string" @bind-Items="steps" Disabled="locked"
            aria-label="Onboarding steps" class="sortable-list" Context="s">
    <BhSortableHandle TItem="string" class="sortable-handle"
                      aria-label="@($"Reorder {s.Item}")">⠿</BhSortableHandle>
    <span class="sortable-title">@s.Item</span>
</BhSortable>

@code {
    private bool locked = true;
    private IList<string> steps = ["Create account", "Verify email", "Invite teammates", "Connect a repository"];
