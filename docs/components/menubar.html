Menubar

A desktop-style application menu bar — menus, submenus, checkable items and keyboard shortcuts — with zero visual opinion.

Application menubar

The WAI-ARIA menubar pattern: the bar is a single tab stop, ← / → move between menus (and switch the open one), ↓ / Enter / Space open a menu, ↑ / ↓, Home / End and typeahead move inside it, → / ← open and close submenus, and Escape closes. Once a menu is open, hovering another trigger switches to it. Checkbox (menuitemcheckbox) and radio (menuitemradio) items keep the menu open and show their state through BhMenuItemIndicator; BhMenuLabel names its BhMenuGroup. The shortcuts are just text.

    border-radius: 0.4rem;
    background: transparent;
    font: inherit;
    font-size: 0.875rem;

    user-select: none;
    transition: background-color 120ms ease;

.menubar-trigger:focus-visible      { background: #f4f4f5; outline: 2px solid #2563eb; outline-offset: 1px; }
.menubar-trigger[data-disabled]     { opacity: 0.4; cursor: not-allowed; background: transparent; }

/* BhMenuItems / BhMenuSubContent — positioned by the anchor engine */
.menubar-content {
    z-index: 50;
    min-width: 14rem;
    padding: 0.25rem;
    background: #fff;
    border: 1px solid #e4e4e7;
    border-radius: 0.6rem;
    box-shadow: 0 10px 30px -6px rgba(0, 0, 0, 0.15);
    outline: none; /* the highlighted item is the visible focus (aria-activedescendant) */
}

.menubar-content[hidden]             { display: none; }
.menubar-content[data-state="open"]  { animation: menubar-in 120ms ease-out; }

/* Opacity only: the anchor engine measures the panel, so don't transform it */

    from { opacity: 0; }

Disabled menus and items

A disabled BhMenu can't be opened and ← / → skip over it; disabled items stay visible (with data-disabled and aria-disabled) but arrow keys and typeahead pass them by. Loop="false" stops the arrow keys at the first and last menu instead of wrapping. Items can also render as links with As="a" — Enter follows the link.
